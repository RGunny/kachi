# Kachi 개발가이드

코드 작성 관례(convention)의 단일 출처다. 문서 간 축 분담은 다음과 같다. 
- 구조와 의존 규칙은 [아키텍처.md](아키텍처.md), 
- 테스트 작성 기준은 [테스트전략.md](테스트전략.md), 
- 도메인 지식은 [도메인모델.md](도메인모델.md),
- 결정의 배경은 [decisions/](decisions/)에 있다. 
이 문서는 "코드를 어떤 모양으로 쓰는가"만 다룬다.

## 기술 스택

- Kotlin 2.2.21, Spring Boot 4.0.6, Java 21+
- user-service: Spring Data JPA + MySQL (Flyway), Redis(refresh token)
- collector/ai-service: Spring Data MongoDB (Reactive), WebClient
- notification: MongoDB(replica set, 트랜잭션), Redis(dedupe/idempotency), Kafka
- 테스트: JUnit 5, Testcontainers 2.0, ArchUnit
- 멀티모듈: user-service, collector-service, ai-service, notification-contract,
  notification-core, notification-service, notification-worker.
  서비스 간 공유 모듈은 notification-contract 하나만 허용한다.

## 도메인 모델 관례

[도메인모델.md](도메인모델.md)의 공통 모델 관례를 코드로 구현하는 규칙이다.

- aggregate/entity는 `class` + `private constructor` + companion 정적 팩터리.
  신규 생성(`create`/`start`/`register`/`request`/`track`/`initial`)과 저장소 복원(`restore`)을 분리한다. 
  신규 생성은 불변식을 검증하고 초기 상태를 결정하며, `restore`는 snapshot 정합만 검증한다.
- 상태 변경은 의미 있는 도메인 메서드로만 한다. setter를 두지 않는다.
  - user/collector/ai: 불변 객체. 변경 메서드는 새 인스턴스를 반환한다.
  - notification 상태 기계: `private set` 가변 프로퍼티 + 전이 가드. 잘못된 전이는 `IllegalStateException`, 같은 상태 재전이는 멱등 무시.
- 식별자는 `@JvmInline value class` id VO. `newId()`는 `UuidCreator.getTimeOrderedEpoch()` (UUID v7, ADR 003), `of(value)`는 저장소 값 복원.
- 값 객체는 `private constructor` + `of()` 정적 팩터리에서 정규화(trim/lowercase)와 검증을 마친다. 
  검증은 `require(조건) { "한국어 메시지" }`.
- 파생 값은 저장 필드가 아니라 파생 프로퍼티로 둔다 (`LlmFailure.source`, `NewsUrl.hash`). 
  분류 축이 어긋난 상태를 만들 수 없게 한다.
- 시간은 도메인이 만들지 않는다. application 계층이 `Clock`으로 `Instant`를 생성해 파라미터로 전달한다. 
  도메인 코드에 `Instant.now()`를 쓰지 않는다.
- 도메인은 Spring, JPA, Mongo, Kafka 등 기술에 의존하지 않는다.

## 예외 관례

모듈 접두어를 붙인 `ErrorCode` 인터페이스 + 추상 예외 한 쌍이 모듈 예외 체계의 뿌리다.
application 예외는 전부 이 추상 예외를 상속하고 `errorCode`를 가진다.

```kotlin
interface AiErrorCode {            // 모듈별: NotificationErrorCode(ErrorCode), Collector/User는 R2·R3
    val code: String
    val message: String
}

abstract class AiException(
    val errorCode: AiErrorCode,
    message: String = errorCode.message,
    cause: Throwable? = null,
) : RuntimeException(message, cause)
```

- 모듈 간 코드 의존은 두지 않는다. bounded context 독립을 유지하고 규약의 모양만 맞춘다 (ADR 021). 
  공용 모듈 추출은 세 서비스가 같은 모양이 된 뒤 별도 판단한다.
- code는 번호가 아니라 의미 코드다 (`KEYWORD_READER_REQUEST_FAILED`).
  enum 상수명은 "무엇이 실패했나", code 문자열은 "어느 모듈의 무엇인가"를 담는다.
- `"<code> <message>: <detail>"` 조립은 모듈 예외의 companion(`messageOf`) 한 곳에 둔다.
  하위 클래스마다 조립 로직을 복붙하지 않는다.
- Retryable/NonRetryable 같은 예외 타입 분기는 프레임워크 경계가 예외 Class를 요구할 때만 만든다 (notification의 spring-kafka 경계). 
  값 판정으로 충분하면 실패 모델(`LlmFailure`, `RetryFailure`)의 필드로 분류를 표현한다 (ADR 021).
- 경계 전용 예외는 그 경계의 어댑터 패키지에 둔다
  (예: worker `adapter/inbound/messaging/exception/`).

## 패키지 구조 관례

기본 골격은 [아키텍처.md](아키텍처.md)를 따르고, port/adapter 하위는 다음 규칙이다.

```text
application/port/inbound/<feature>/          ← 유스케이스 인터페이스만
application/port/inbound/<feature>/model/    ← 그 인터페이스의 파라미터/리턴 타입
application/port/outbound/<feature>/         ← 아웃바운드 포트 인터페이스만
application/port/outbound/<feature>/model/   ← 그 포트의 파라미터/리턴 타입
adapter/inbound/... , adapter/outbound/...
```

- `in`/`out`이 아니라 `inbound`/`outbound`다. `in`은 Kotlin 키워드라 백틱 import를 강요한다.
- `model/`은 feature마다 하나다. 포트가 도메인 객체만 주고받으면 만들지 않는다.
- `response/`, `command/`, `exception/` 같은 종류별 서브패키지는 만들지 않는다.
  예외는 `application/exception`에 자리가 있다.
- 타입 배치는 그 타입을 시그니처에 쓰는 포트를 따라간다. 여러 포트가 쓰면 생산자 포트의 feature에 두고 나머지가 import한다.
- port model은 VO가 아니다. 포트 시그니처가 존재 이유의 전부다. model 타입이 여러 포트를 넘나들거나 
  도메인 로직이 다루기 시작하면 `domain/` 승격 신호이고, domain 타입이 특정 포트에서만 쓰이면 model로 내려올 후보다.
- `dto`라는 이름은 진짜 전송 경계 객체(vendor payload, HTTP 요청/응답)에만 쓴다.

## 어댑터 관례

- 인바운드 어댑터는 요청 DTO를 application command/query로 변환해 유스케이스 포트를 호출한다. 
  도메인은 웹 DTO를 직접 받지 않는다.
- internal API는 `ApiPaths`/`ApiVersions` 상수와 `ApiResponse` 봉투 규약을 따른다.
  버전 정책은 [아키텍처.md](아키텍처.md#api-버전-정책) 참조.
- 외부 API client는 WebClient 기반 아웃바운드 어댑터로 두고, provider별 응답 구조·인증·보정은 어댑터 안에서 끝낸다. 
  application에는 포트 모델만 넘긴다.
- 외부 실패는 어댑터에서 분류해 실패 모델로 변환한다 (호출 1회 + 분류 + Retry-After 보존).
  in-process 재시도 루프를 두지 않는다 — 재시도는 영속 상태(outbox, watermark tick)가 구동하고, 
  in-process에는 호출 차단(CircuitBreaker)만 둔다.
- Spring Data repository와 persistence entity(document)는 `adapter/outbound/persistence`에 두고, 
  도메인 객체와의 변환을 어댑터가 담당한다.

## 테스트 관례

작성 기준과 인프라 정책은 [테스트전략.md](테스트전략.md)가 단일 출처다. 코드 모양 관례만 적는다.

- 모듈별 test fixture object에 고정 시간 상수를 둔다. 모듈 간 테스트 공유 모듈은 만들지 않는다.

```kotlin
object AiTestFixture {
    val NOW: Instant = Instant.parse("...")
    val CLOCK: Clock = Clock.fixed(NOW, ZoneOffset.UTC)
}
```

- 시나리오 고유 시간은 `NOW.plus(...)` 상대값으로 표현한다.
- application service 단위 테스트는 Fake 포트 구현으로 작성한다. mocking 프레임워크보다 Fake를 우선한다.
- 외부 HTTP 어댑터 단위 테스트는 fake `ExchangeFunction`으로 요청/응답 계약을 검증한다.
- 테스트 데이터 생성은 fixture의 정적 메서드로 모은다.

## 네이밍

- 인바운드 포트: `<행위>UseCase` (`SummarizeNewsUseCase`)
- 아웃바운드 포트: `<대상><역할>Port` (`NewsReaderPort`, `KeywordPersistencePort`) 또는
  역할 명사 (`NotificationSender`, `NotificationDispatchPublisher`)
- 유스케이스 구현: `<행위>Service` (`SummarizeNewsService`)
- 어댑터: `<대상><기술|역할>Adapter` (`UserServiceKeywordReaderAdapter`)
- 예외: 모듈 접두어 기반 (`AiException` 계열), 상황 서술 (`KeywordReaderException`)
- 에러 코드: `<주체>_<실패내용>` 의미 코드

## 주석 관례

- KDoc은 "왜"를 적는다. 결정 배경이 ADR에 있으면
  `docs/decisions/NNN-....md 를 참고한다`로 연결한다.
- 소스 주석은 그 파일의 책임만 서술한다. 다른 모듈과의 설계 대조("notification과 달리...")는
  소스가 아니라 ADR에 적는다.
- 코드가 보여주는 것(다음 줄이 무엇을 하는지)은 주석으로 반복하지 않는다.
