# Kachi 문서 지도

docs/의 각 문서는 축이 하나다. 같은 내용을 두 문서에 적지 않고, 겹치는 지점은 링크로
연결한다. 새 문서를 만들기 전에 이 표에서 자리가 있는지 먼저 확인한다.

## 도메인모델 문서 규칙

- 컨텍스트별 파일로 나눈다: `도메인모델-{context}.md`, context는 영문 소문자
  (`user`, `collector`, `ai`, `notification`, `history`). 새 컨텍스트가 생기면 같은
  규칙으로 파일을 추가하고 index([도메인모델.md](도메인모델.md)) 표에 등록한다.
- 요소 템플릿: `### 한글명(영문클래스명)` + 스테레오타입(_Aggregate Root_ / _Entity_ /
  _Value Object_ / _Enum_ / _Domain Service_) + `#### 속성(Attributes)` /
  `#### 행위(Behaviors)` / `#### 규칙(Rules)`.
- 이 문서 계열은 코드의 요약이 아니라 선행 원장이다. 새 개념은 코드보다 먼저 문서와
  용어사전에 자리를 잡고, 미구현 개념은 "(계획, 미구현)"으로 표시해 남긴다.
- 도메인 코드를 바꾸는 커밋은 해당 컨텍스트 문서 갱신을 포함하는 것을 기본으로 한다.
  규칙(불변식, 상태 전이)이 바뀌었는데 문서가 그대로면 리뷰에서 걸러낸다.

## ADR 규칙

- 파일명: `NNN-주제.md` 3자리 연번. 번호는 재사용하지 않는다.
- 확정된 ADR의 결정을 바꿀 때는 본문을 고치지 않고 개정 노트를 추가한다.
- 반려한 대안도 이유와 함께 기록한다 (같은 논의의 반복 방지).
- 문서 규칙 중 코드로 강제할 수 있는 것(계층 의존 등)은 ArchUnit 테스트로 옮기고,
  문서는 무엇이 강제되는지 알려주는 색인이 된다.
