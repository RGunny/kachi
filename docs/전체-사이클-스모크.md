# 전체 사이클 스모크

실제 LLM(Groq)과 실제 채널(Slack·Discord·Telegram)로 수집 → 요약 → 알림 수신을 사람이 확인하는 절차다.
테스트는 실제 provider와 vendor를 부르지 않으므로([테스트전략.md](테스트전략.md)), 실제 연결은 여기서만 확인한다.
자동 검증은 `./gradlew :e2e-test:e2eTest`가 stub LLM과 mock sender로 같은 경로를 돈다(ADR 029).

## 전제

- Docker Desktop이 기동되어 있다.
- `.env.local`에 다음 키가 있다. 키 목록은 `.env.example`.

| 키 | 용도 |
| --- | --- |
| `GROQ_API_KEY` | ai-service가 부르는 LLM. 스크립트가 다른 provider를 끄므로 이 키만 있으면 된다 |
| `KACHI_USER_SEED_ADMIN_SLACK_WEBHOOK_URL` | 관리자 계정의 Slack 바인딩 주소. `https://hooks.slack.com/`으로 시작해야 한다 |
| `KACHI_USER_SEED_ADMIN_DISCORD_WEBHOOK_URL` | 관리자 계정의 Discord 바인딩 주소. `https://discord.com/api/webhooks/`로 시작해야 한다 |
| `KACHI_USER_SEED_ADMIN_TELEGRAM_CHAT_ID` | 관리자 계정의 Telegram chat id |
| `KACHI_NOTIFICATION_TELEGRAM_BOT_TOKEN` | worker의 Telegram 봇 토큰 |
| `NAVER_CLIENT_ID`·`NAVER_CLIENT_SECRET` 또는 `FINNHUB_API_KEY` | collector-service 뉴스 provider. Google RSS는 키가 없다 |

수신자는 local seed의 관리자 계정(`admin@kachi.local`)이다.

- seed가 이 계정에 세 채널 바인딩을 위 주소로 만든다.
- 시드 키워드 5개(`TRUMP`·`NVIDIA`·`SPACE-X`·`TESLA`·`이란`)를 세 채널로 구독시킨다.
- 공개 API로 구독을 넣으려면 OAuth 로그인이 필요해서 seed가 대신한다.

## 기동

```sh
./scripts/cycle.sh start
```

순서: 인프라(mysql·redis·mongo·kafka) → Kafka 준비 대기 → Mongo index 스크립트 2개 → user-service → 나머지 5개.

- ai-service에는 `KACHI_AI_EVENTS_ENABLED=true`·`KACHI_AI_OUTBOX_RELAY_ENABLED=true`와 groq 외 provider `enabled=false`가 env로 들어간다.
- scheduler는 켜지 않고 아래에서 internal API로 tick을 돌린다.

기동 확인:

```sh
./scripts/cycle.sh status
curl -s localhost:8080/actuator/health && curl -s localhost:8083/actuator/health
```

## 확인 절차

각 단계의 결과를 보고 다음으로 간다. 막히면 해당 서비스 로그(`./scripts/app.sh <service> logs`)를 본다.

1. **seed 확인**
   - 관리자 바인딩이 실주소로 들어갔는지 본다.
   ```sh
   ADMIN_ID=$(curl -s 'localhost:8080/api/v1/internal/users?role=ADMIN' | jq -r '.data[0].userId')
   curl -s "localhost:8080/api/v1/internal/users/$ADMIN_ID/channel-bindings/SLACK" | jq .data
   curl -s 'localhost:8080/api/v1/internal/subscriptions?keyword=NVIDIA' | jq .data
   ```
   - `status`가 `ACTIVE`이고 `address`가 `.env.local`의 값이어야 한다.
   - 구독 목록에 관리자 id가 세 채널로 있어야 한다.
2. **뉴스 수집**
   - collector가 시드 키워드로 수집한다.
   ```sh
   curl -s -X POST localhost:8082/api/v1/internal/collections/news | jq
   curl -s 'localhost:8082/api/v1/internal/news?keyword=NVIDIA&limit=5' | jq '.data | length'
   ```
   - 0이면 provider 키나 네트워크를 본다.
   - 다음 단계는 뉴스가 있는 키워드로 진행한다.
3. **요약**
   - ai-service가 Groq를 부르고 outbox에 넣는다.
   ```sh
   curl -s -X POST localhost:8083/api/v1/internal/ai/news-summaries \
     -H 'Content-Type: application/json' -d '{"keywords":["NVIDIA"]}' | jq
   curl -s localhost:8083/api/v1/internal/ai/outboxes | jq '.data[] | {eventType, status, partitionKey}'
   ```
   - `succeededCount`가 1이고 outbox 행이 몇 초 안에 `PUBLISHED`가 되어야 한다.
   - 실패하면 `GET /api/v1/internal/providers/llm`으로 groq 상태(서킷·cooldown)를 본다.
4. **라우팅**
   - routing이 구독자 x 채널로 fan-out해 접수 이벤트를 발행한다.
   ```sh
   ./scripts/app.sh notification-routing logs      # "ai summary routed eventKey=... targets=3 published=3" 확인
   ```
5. **접수·발송**
   - notification-service가 접수하고 worker가 보낸다.
   ```sh
   docker exec -i kachi-mongo mongosh --quiet kachi_notification --eval \
     'db.notifications.find({}, {requestId:1, channel:1, status:1, _id:0}).sort({requestedAt:-1}).limit(6)'
   ```
   - 관리자의 세 채널이 `SENT`여야 한다.
   - `SUPPRESSED`면 사유(`failureReason`)를 본다.
     바인딩이 없거나 24시간 안에 같은 requestId로 이미 보낸 것이다.
6. **실제 수신**
   - Slack 채널, Discord 채널, Telegram 대화에 요약 메시지가 왔는지 눈으로 확인한다.
   - 세 채널 모두 와야 끝이다.

## 재실행

같은 뉴스로 다시 돌리면 아무 일도 일어나지 않는다.

- 요약은 `(keyword, newsHash)`로 재사용되어 이벤트가 나지 않는다.
- 이벤트가 나더라도 같은 `requestId`는 접수에서 걸린다.
- 24시간 안이면 `notification:sent:{requestId}` 가드에 걸린다 ([알림-멱등-가드.md](알림-멱등-가드.md)).

다시 돌리는 방법:

- **다른 키워드로**: 3단계에서 `keywords`를 바꾼다. 가장 간단하다.
- **같은 키워드로 새 요약을 만들려면**: ai-service의 요약과 watermark를 지운다.
  ```sh
  docker exec -i kachi-mongo mongosh --quiet kachi_ai --eval \
    'db.news_summaries.deleteMany({keyword:"nvidia"}); db.ai_summary_watermarks.deleteMany({})'
  ```
  새 summaryId가 나오므로 requestId도 새것이다.
- **같은 알림을 다시 보내려면**(운영 복구 상황 재현): 가드 키를 지운다.
  - 알림 상태도 `REQUESTED`로 되돌려야 하므로 평소에는 위 두 방법을 쓴다.
  ```sh
  docker exec -i kachi-redis redis-cli --scan --pattern 'notification:sent:*' | xargs -r docker exec -i kachi-redis redis-cli DEL
  ```

## 정지

```sh
./scripts/cycle.sh stop
```

데이터는 compose volume에 남는다. 완전히 비우려면 `docker compose -p kachi down -v`.
