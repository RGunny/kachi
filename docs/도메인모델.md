# Kachi Domain Model

## Domain Overview

Kachi는 사용자가 등록한 관심 키워드를 기준으로 뉴스와 시장 데이터를 수집하고, AI로 키워드를 확장하거나 뉴스를 요약한 뒤, 사용자가 설정한 채널로 알림을 발송하는 서비스다.

서비스는 다음 bounded context로 나눈다.

| Context | Service | Responsibility |
| --- | --- | --- |
| User | user-service | 사용자 인증, 사용자 상태, 관심 키워드 관리 |
| Collector | collector-service | 외부 뉴스/시장 데이터 수집 및 저장 |
| AI | ai-service | 키워드 확장, 뉴스 요약, 감성 판단 |
| Notification | notification-service | 알림 요청 접수, outbox, 채널별 발송, 재시도 |
| History | history-service | 사용자별 뉴스/요약/알림 이력 적재 및 통계 집계 |

## User Aggregate

### User

_Aggregate Root_

#### Attributes

- `id`: 사용자 식별자
- `email`: 로그인 이메일
- `nickname`: 사용자 표시 이름
- `status`: 사용자 상태
- `role`: 사용자 권한
- `authProvider`: 인증 제공자
- `providerUserId`: OAuth provider가 제공하는 사용자 식별자
- `registeredAt`: 가입 일시
- `lastLoginAt`: 마지막 로그인 일시
- `deactivatedAt`: 탈퇴 일시

#### Behaviors

- `register()`: 사용자를 등록한다.
- `restore()`: 저장소에 있던 사용자 상태를 도메인 객체로 복원한다.
- `activate()`: 사용자를 활성화한다.
- `recordLogin()`: 로그인 성공 시각을 기록한다.
- `deactivate()`: 사용자를 탈퇴 상태로 변경한다.

#### Rules

- 이메일은 중복될 수 없다.
- 신규 등록은 `register()`를 사용하고, 저장소 조회 결과 복원은 `restore()`를 사용한다.
- `register()`, `recordLogin()`, `deactivate()`에 필요한 현재 시각은 application 계층에서 `Clock`으로 생성해 `Instant`로 전달한다.
- 활성 사용자만 키워드를 등록, 수정, 삭제할 수 있다.
- 활성 사용자만 로그인 시각을 기록할 수 있다.
- 탈퇴 사용자는 키워드를 변경할 수 없다.
- OAuth 사용자는 인증 제공자와 provider user id로 식별할 수 있어야 한다.
- LOCAL 사용자는 provider user id를 가지지 않는다.

### Email

_Value Object_

#### Attributes

- `value`: 이메일 주소

#### Behaviors

- `of()`: 문자열을 정규화하고 이메일 값 객체를 생성한다.

#### Rules

- 이메일은 빈 값일 수 없다.
- 이메일은 소문자로 정규화한다.
- 이메일은 255자를 초과할 수 없다.

### UserId

_Value Object_

#### Attributes

- `value`: 사용자 식별 UUID

#### Behaviors

- `newId()`: 신규 사용자 식별자를 생성한다.
- `of()`: 저장소에 있던 UUID를 사용자 식별자로 복원한다.

#### Rules

- 사용자 식별자는 `UserId` 타입으로 표현한다.
- 다른 aggregate 식별자와 UUID 값을 직접 섞어 쓰지 않는다.

### Nickname

_Value Object_

#### Attributes

- `value`: 사용자 표시 이름

#### Behaviors

- `of()`: 문자열을 정규화하고 닉네임 값 객체를 생성한다.

#### Rules

- 닉네임은 빈 값일 수 없다.
- 닉네임 앞뒤 공백은 제거한다.
- 닉네임은 100자를 초과할 수 없다.

### Keyword

_Entity_

#### Attributes

- `id`: 키워드 식별자
- `userId`: 키워드를 소유한 사용자 식별자
- `name`: 키워드 이름
- `enabled`: 수집 대상 포함 여부
- `registeredAt`: 키워드 등록 일시
- `disabledAt`: 키워드 비활성화 일시

#### Behaviors

- `create()`: 키워드를 등록한다.
- `restore()`: 저장소에 있던 키워드 상태를 도메인 객체로 복원한다.
- `rename()`: 키워드 이름을 변경한다.
- `enable()`: 키워드를 수집 대상으로 포함한다.
- `disable()`: 키워드를 수집 대상에서 제외한다.

#### Rules

- 키워드는 반드시 한 명의 사용자에게 속한다.
- 한 사용자는 같은 이름의 키워드를 중복 등록할 수 없다.
- 신규 등록은 `create()`를 사용하고, 저장소 조회 결과 복원은 `restore()`를 사용한다.
- `create()`와 `disable()`에 필요한 현재 시각은 application 계층에서 `Clock`으로 생성해 `Instant`로 전달한다.
- 비활성 키워드는 뉴스 수집 대상에서 제외된다.
- 이미 비활성화된 키워드는 다시 비활성화할 수 없다.

### KeywordId

_Value Object_

#### Attributes

- `value`: 키워드 식별 UUID

#### Behaviors

- `newId()`: 신규 키워드 식별자를 생성한다.
- `of()`: 저장소에 있던 UUID를 키워드 식별자로 복원한다.

#### Rules

- 키워드 식별자는 `KeywordId` 타입으로 표현한다.

### KeywordName

_Value Object_

#### Attributes

- `value`: 키워드 이름

#### Behaviors

- `of()`: 문자열을 정규화하고 키워드 이름 값 객체를 생성한다.

#### Rules

- 키워드는 빈 값일 수 없다.
- 키워드 앞뒤 공백은 제거한다.
- 키워드는 100자를 초과할 수 없다.

## Collector Context

### News

_Aggregate Root_

#### Attributes

- `id`: 뉴스 식별자
- `source`: 뉴스 출처
- `title`: 제목
- `url`: 원문 URL
- `publishedAt`: 발행 시각
- `keyword`: 수집 기준 키워드

#### Rules

- 같은 출처의 같은 URL은 중복 저장하지 않는다.
- 제목과 URL이 없는 뉴스는 저장하지 않는다.

### MarketData

_Aggregate Root_

#### Rules

- 시장 데이터는 뉴스 요약의 보조 정보로 사용한다.
- 외부 API 실패는 전체 수집 흐름을 중단시키지 않고 실패 이력으로 남긴다.

## AI Context

### KeywordExpansion

_Aggregate Root_

#### Rules

- 확장 키워드는 원본 키워드와 함께 추적되어야 한다.
- LLM 응답이 비어 있거나 파싱할 수 없으면 실패로 처리한다.

### Summary

_Aggregate Root_

#### Rules

- 요약은 어떤 뉴스 묶음에서 생성되었는지 추적할 수 있어야 한다.
- 요약 결과에는 사용한 LLM provider와 생성 시각을 남긴다.

## Notification Context

### Notification

_Aggregate Root_

#### Rules

- 알림 요청은 idempotency key로 중복 발송을 방지한다.
- 채널별 발송 실패는 재시도 정책에 따라 처리한다.

### NotificationOutbox

_Entity_

#### Rules

- 알림 이벤트는 outbox에 먼저 저장한 뒤 비동기로 발행한다.
- 발행 완료, 실패, 재시도 상태를 기록한다.

---

## History Context

### History

_Aggregate Root_

#### Rules

- 사용자별 뉴스, 요약, 알림 결과를 장기 조회할 수 있어야 한다.
- notification-service의 발송 처리 상태와 history-service의 장기 이력은 책임을 분리한다.
