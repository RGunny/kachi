# 포트 구성

## 목적과 범위

이 문서는 local 프로필에서 Kachi를 실행할 때 사용하는 TCP 포트를 한곳에서 관리한다.
포트는 다음 세 종류로 구분한다.

- **호스트 공개 포트**: 브라우저, curl, host에서 실행한 애플리케이션이 접속하는 `localhost:{port}`이다.
- **컨테이너 인바운드 포트**: Docker network 안에서 컨테이너가 수신하는 포트다. 호스트에 공개하지 않을 수 있다.
- **애플리케이션 인바운드 endpoint**: HTTP 서버가 수신하는 API 또는 Actuator 경로다. endpoint는 포트와 함께 기록한다.

외부 provider로 나가는 HTTP 요청은 OS가 할당하는 ephemeral source port를 사용한다. 따라서 Google News, LLM, Slack 등 provider별 고정 **outbound local port**는 없다. 이 문서는 앱이 수신하거나 Docker가 publish하는 포트를 대상으로 한다.

## 포트 충돌 검토

기본값 기준 중복된 호스트 공개 포트는 없다.

| 범위 | 포트 |
| --- | --- |
| 애플리케이션 HTTP | `8080`, `8082`, `8083`, `8084`, `8085` |
| 로컬 인프라 | `3306`, `6379`, `9092`, `27017` |
| 관측성 UI/API | `3000`, `9094` |
| 개발 frontend (프로젝트 외부) | `5173` |

`8081`은 현재 예약하거나 사용하지 않는다. Prometheus의 컨테이너 내부 포트는 `9090`이지만 호스트에는 `9094`로 publish하므로 Kafka controller 내부 포트 `9093`과 충돌하지 않는다.

환경 변수로 인프라 포트를 바꾸면 해당 local profile의 접속 URL도 함께 바꿔야 한다. 예를 들어 `KAFKA_PORT=19092`라면 `KAFKA_BOOTSTRAP_SERVERS=localhost:19092`도 맞춘다.

## 호스트 공개 포트와 인바운드 endpoint

| 호스트 포트 | 소유자 | 인바운드 용도 | 주요 endpoint 또는 protocol | 설정 원천 |
| --- | --- | --- | --- | --- |
| `3000` | Grafana | 관측성 UI | `http://localhost:3000` | `infra/docker-compose.observability.yml` |
| `3306` | MySQL | user-service persistence | MySQL protocol | `MYSQL_PORT` (기본 `3306`) |
| `5173` | local frontend, 프로젝트 외부 | OAuth2 callback 수신 | `/oauth2/callback` | user-service local profile |
| `6379` | Redis | refresh token, notification dedupe/idempotency | Redis protocol | `REDIS_PORT` (기본 `6379`) |
| `8080` | user-service | 사용자 API와 internal keyword API | `/api/v1/*`, `/actuator/health` | `user-service/application.yaml` |
| `8082` | collector-service | 수집 제어와 AI용 뉴스 조회 API | `/api/v1/internal/*`, `/actuator/health` | `collector-service/application.yaml` |
| `8083` | ai-service | AI 수동 실행과 LLM health API | `/api/v1/internal/*`, `/actuator/health` | `ai-service/application.yaml` |
| `8084` | notification-service | notification HTTP API와 Prometheus scrape | `/api/v1/*`, `/actuator/health`, `/actuator/prometheus` | `notification-service/application.yaml` |
| `8085` | notification-worker | worker management endpoint와 Prometheus scrape | `/actuator/health`, `/actuator/prometheus` | `notification-worker/application.yaml` |
| `9092` | Kafka broker | Spring Kafka producer/consumer 접속 | Kafka PLAINTEXT protocol | `KAFKA_PORT` (기본 `9092`) |
| `9094` | Prometheus | Prometheus UI/API | `http://localhost:9094` | observability Compose의 `9094:9090` mapping |
| `27017` | MongoDB replica set | collector, AI, notification persistence | MongoDB protocol | `MONGO_PORT` (기본 `27017`) |

`8084`와 `8085`는 Prometheus가 Docker 컨테이너에서 `host.docker.internal`을 통해 scrape한다. 따라서 local observability stack을 실행할 때 notification-service와 worker는 host에서 각각 이 포트로 실행돼 있어야 한다.

## 컨테이너 내부 포트

| 컨테이너/서비스 | 내부 포트 | 외부 publish | 설명 |
| --- | --- | --- | --- |
| Grafana | `3000` | host `3000` | Grafana HTTP UI |
| Prometheus | `9090` | host `9094` | Prometheus HTTP UI/API 및 내부 datasource 주소 |
| Kafka broker | `9092` | host `9092` | 애플리케이션 Kafka client 접속 |
| Kafka controller | `9093` | 없음 | KRaft controller 통신 전용이며 host client가 사용하지 않음 |
| MySQL | `3306` | host `3306` | user-service 데이터베이스 |
| Redis | `6379` | host `6379` | token/dedupe 저장소 |
| MongoDB | `27017` | host `27017` | collector, AI, notification 데이터베이스 |

Grafana 컨테이너는 `http://prometheus:9090`으로 Prometheus에 접속한다. 여기서 `prometheus`는 외부 DNS 이름이 아니라 `obs-network`의 Compose service 이름이다.

## 서비스 간 인바운드 연결

| 호출자 | 대상 | 대상 포트 | 인바운드 계약 |
| --- | --- | --- | --- |
| collector-service | user-service | `8080` | `GET /api/v1/internal/keywords/active` |
| ai-service | user-service | `8080` | `GET /api/v1/internal/keywords/active` |
| ai-service | collector-service | `8082` | `GET /api/v1/internal/news` |
| Prometheus | notification-service | `8084` | `GET /actuator/prometheus` |
| Prometheus | notification-worker | `8085` | `GET /actuator/prometheus` |
| user/collector/AI/notification runtime | Kafka | `9092` | Kafka producer/consumer protocol |

현재 `notification.requested`를 발행하는 upstream producer는 구현되어 있지 않다. notification-service의 Kafka listener가 사용할 인바운드 포트는 `9092`이며, topic은 포트가 아니라 Kafka 내부 논리 채널이다.

## 실행 전 확인

기본 포트가 이미 다른 프로세스에 사용 중인지 확인한다.

```sh
lsof -nP -iTCP -sTCP:LISTEN | rg ':(3000|3306|6379|8080|8082|8083|8084|8085|9092|9094|27017)( |$)'
```

macOS에서 사용 중인 포트가 있으면 해당 프로세스를 종료하거나 `.env.local`의 인프라 포트를 변경한다. 애플리케이션 HTTP 포트는 해당 서비스의 local profile 또는 실행 환경 변수와 함께 변경해야 하며, 이를 참조하는 client `base-url`과 Prometheus target도 같은 값으로 맞춘다.

## 보안 경계

현재 포트는 local 개발 편의를 위한 host 공개 설정이다. 운영 환경에서는 MySQL, Redis, MongoDB, Kafka, Prometheus를 host에 직접 publish하지 않고 private network로 제한한다. Grafana도 기본 `admin/admin` 및 anonymous viewer 설정을 운영에 사용하면 안 된다.
